Choose and clone an architecture

Five shipped templates, and how to clone one.

Barnark has no favourite. The description of each shipped template says where it suits, and the choice is yours. template:list lists them:

$ vendor/bin/barnark template:list
Barn: …/hotel
 ---------------------------- ------------
  Name                         What it is
 ---------------------------- ------------
  Domain Driven Design         Shipped
  Feature Based Architecture   Shipped
  Model View Controller        Shipped
  Library                      Shipped
  Package App                  Shipped
TemplateWhat it isSuits
Domain Driven DesignCode organised around the business: bounded contexts, each with its own domain model, an application layer of commands and queries, and infrastructure, over a shared kernel with transports at the edge.A long-lived application with rich business rules and several distinct parts of the business.
Feature Based ArchitectureOne self-contained folder per feature, holding its own entities, values, exceptions, repositories and controllers.A small or medium application whose features change independently, where full layering would be overhead.
Model View ControllerThe classic three-way split: controllers take requests, models hold data and rules, views present them.A conventional web application, especially one built on an MVC framework.
LibraryA small public Api over hidden Internal code, split into features and shared parts.A reusable package whose users should depend only on a stable surface.
Package AppA whole application packaged behind a public Api, with bounded contexts, features and a kernel inside.An application that other code installs and drives as a dependency.

See what a clone would make #

--dry-run checks the template, the name and the target, and prints the folders it would make without writing anything. Each of these was run in a barn with nothing bound.

Feature Based Architecture is built entirely from members, so a clone makes only the folder. Its features arrive as you add them: Add folders to your template shows how.

Clone it #

$ vendor/bin/barnark template:clone "Domain Driven Design" Hotel ./src
Barn: …/hotel

Cloning 'Hotel', a copy of 'Domain Driven Design', into ./src
=============================================================

  ./src
  …

 [OK] Cloned 'Hotel' into ./src.

Bound to the template 'Hotel' in .barn/barnark/tracked-folders.json — check it any time with `barnark template:check`.
  • The first argument names a template: a shipped one, or one of your own as template:list shows it.
  • The second is the name for the project’s template, your own copy. Nobody calls a project “Domain Driven Design”, so a shipped template’s name is refused.
  • The third is the folder to make. It is relative to the barn’s root, and the folder above it must exist.
$ vendor/bin/barnark template:clone Library X ./nope/lib
Barn: …/hotel

 [ERROR] Folder '/nope' does not exist. Create that one first.

Each folder made has a .gitkeep, so that git keeps it while it is empty. Barnark creates no other file in your folders. The folder is recorded in .barn/barnark/tracked-folders.json and its template is kept in .barn/barnark/catalogue/, so a later template:check with no arguments knows what to check.
