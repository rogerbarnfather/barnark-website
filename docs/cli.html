Command reference

Every command, argument and option.

The barnark command is for a terminal, scripts, CI and AI agents. It does what the browser app does. vendor/bin/barnark <command> --help lists every option of a command.

The commands #

CommandWhat it does
initMake a barn here if there is none, and say where Barnark keeps its records.
skills:installCopy Barnark’s agent skills into the project.
template:listList the bound template, your own and the shipped ones.
template:clone <template> <name> <targetDir>Clone a template into the project under a name you give, and make its folder.
template:check [<template> [<directory>]]Check the bound folder against its template, or a directory against a shipped template.
template:offers [<path>]List what the template lets you create in a folder.
template:new <slot> <name> [<path>]Add a member the folder offers, under a name you give, to the template and make its folder.
template:add-folder <path> <meaning>Add a folder of your own to the template, or take in one made by hand.
template:change-meaning <path> <meaning>Change what a folder of the template, or the bound folder, means.
template:copy <from> <name>Copy any template into a new one of your own.
template:delete <template>Delete one of your templates, with every revision.
guiServe the browser app and open it. It needs rmb32/barnark-gui.

list and help are there too, and completion prints a shell completion script.

Options every command has #

OptionWhat it does
-h, --helpShow help for the command.
-n, --no-interactionDon’t ask. template:delete goes ahead without asking.
-q, --quietShow only errors.
--silentShow no message at all.
-v, -vv, -vvvMore output.
--ansi, --no-ansiForce colour on or off.
-V, --versionShow Barnark’s version.

The barn #

Barnark keeps its records only in a barn: the project’s .barn/ folder, which every Barn tool shares. init makes one in the current folder. Inside another barn it asks first; with -n it refuses unless you pass --separate-barn. With no barn, every template: command refuses and writes nothing:

$ vendor/bin/barnark template:list
 [ERROR] There is no barn in "…/hotel" or any folder above it: no .barn folder
         was found. Start one with `barnark init`.

Each template: command prints the barn’s root first and works from any folder inside the barn. Folder paths are relative to the barn’s root.

Exit status #

A command exits with 0 when it succeeded, and 1 when it was refused or, for template:check, when the folder doesn’t conform. A refusal says why, and writes nothing.

Examples #

$ vendor/bin/barnark init                                              # make a barn here
$ vendor/bin/barnark template:clone "Domain Driven Design" Hotel ./src   # clone it as Hotel and make src/
$ vendor/bin/barnark template:check                                    # check the bound folder
$ vendor/bin/barnark template:offers src/Context                       # what can be created here?
$ vendor/bin/barnark template:new Context Reservation src/Context      # add a member and make its folders
$ vendor/bin/barnark template:add-folder src/Docs "Design notes."      # add a folder of your own
$ vendor/bin/barnark template:copy Hotel Reservations                  # copy the bound template
$ vendor/bin/barnark template:delete Reservations                      # delete the copy
